# production-deployment Specification

## Purpose
规定线上环境的约定：服务和数据库如何声明、密钥放在哪里、什么时候自动部署、上线后如何检查，以及出问题时如何查日志和回滚。目的是让评审能打开公网地址完整练习，部署者能按文档重复部署和排障。

## Requirements

### Requirement: 环境声明在仓库中
线上环境 SHALL 由仓库中的 Blueprint 文件声明：一个 Web 服务（用仓库的 Dockerfile 构建）和一个 PostgreSQL 17 数据库，放在同一区域，都用免费档。Web 服务 MUST 使用 `/api/health` 作为健康检查，并监听平台指定的端口。

#### Scenario: 从仓库创建环境
- **WHEN** 在 Render 上用这个仓库的 Blueprint 创建环境
- **THEN** 创建出一个 Web 服务和一个数据库，不需要手动填写数据库连接串

### Requirement: 密钥不进仓库
数据库连接串 SHALL 由平台在部署时注入环境变量，仓库中 MUST NOT 出现任何线上密码或连接串。数据库 MUST 只接受平台内网连接，不对公网开放。

#### Scenario: 检查仓库
- **WHEN** 在仓库中搜索线上数据库的主机名或密码
- **THEN** 找不到

### Requirement: 部署条件
main 分支的 CI 通过后，线上服务 SHALL 自动部署这次提交；CI 失败的提交 MUST NOT 自动部署。新版本健康检查不通过时，平台 MUST 继续运行上一个版本。服务启动时 MUST 先完成迁移和写入题库，再通过健康检查（见 service-operations）。

#### Scenario: CI 失败
- **WHEN** 推送到 main 的提交 CI 失败
- **THEN** 线上仍是上一个版本

### Requirement: 上线检查
仓库 SHALL 提供冒烟检查命令，参数是服务地址，依次检查：
1. 健康检查返回正常；
2. 首页返回前端页面；
3. 创建学生；
4. 开始练习；
5. 提交一次作答；
6. 读取会话状态。

任一步失败时，命令 MUST 以非零退出码退出，并输出失败的步骤、HTTP 状态和请求 ID。这个命令对本地 Docker Compose 和线上地址都适用。检查会在数据库里留下一个测试学生，与真实学生一样是匿名的。

#### Scenario: 线上正常
- **WHEN** 对线上地址运行冒烟检查
- **THEN** 6 步全部通过，退出码为 0

#### Scenario: 服务不可用
- **WHEN** 对一个不可达的地址运行冒烟检查
- **THEN** 退出码非零，输出指出第 1 步（健康检查）失败

### Requirement: 运维说明
仓库 SHALL 提供部署说明，覆盖：首次部署的步骤、查看线上日志并按请求 ID 定位、回滚到上一次部署、导出作答数据，以及已知限制（免费实例闲置休眠、免费数据库约 30 天过期、没有自动备份）。

#### Scenario: 按请求 ID 排查
- **WHEN** 学生报告某次提交失败，并说明了大致时间
- **THEN** 按说明可以在线上日志中按时间和路径找到这次请求，再用它的请求 ID 找到这次请求的全部日志
