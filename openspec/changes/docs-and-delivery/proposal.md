# Proposal

## Why

功能部分（A–I）已经完成并上线，但题面的"提交要求"还有几项没有满足：
- README 缺少系统结构、数据模型、统计口径，以及技术与体验取舍的说明；
- AI 协同记录目前是按 change 写的流水账，题面要求的是 2–3 段代表性记录（任务输入、AI 产出、本人修改、验证结果）；
- 没有集中的"验证与限制说明"：测试执行结果、已验证场景、已知问题、未完成项、实际投入时间、外部服务与成本。

明天（11/13）展示，还需要一份演示脚本，并实际演练一遍。

## What Changes

- **README** 按题面"提交要求 2"补全：
  - 项目简介、线上地址、功能与题面要求的对照；
  - 系统结构图（浏览器 → Fastify → PostgreSQL，以及 Render、Cloudflare 和视频生成时用到的外部服务）；
  - 数据模型（表与关系）、统计口径（首次作答与重试如何计入）；
  - 可靠性处理清单（已处理 / 仍有限制）；
  - 关键技术与体验设计的取舍；
  - 文档索引。

  已有的启动、配置、测试、接口、日志、故障排查等内容保留并校对。
- **`docs/ai-collaboration.md`**：3 段代表性记录，引用会话原文节选，每段写明任务输入、AI 产出、本人判断与修改、验证结果；末尾说明分工（哪些由 AI 承担、哪些由本人决定）和 AI 出错的汇总。`ai-log-notes.md` 作为完整过程记录保留。
- **`docs/delivery.md`（验证与限制说明）**：
  - 测试命令与执行结果；
  - 已验证场景与题面要求的对照；
  - 已知问题、未完成项；
  - 实际投入时间、复用内容；
  - 外部服务依赖与成本。
- **干净环境验证**：在临时目录中重新克隆仓库，只按 README 的步骤用 Docker 启动，跑冒烟检查和全部测试，结果记入 `docs/delivery.md`。
- **`docs/demo-script.md`**：展示流程，约 8 分钟，包括开场前唤醒免费实例、各环节要点、备用方案（线上不可用时改用本地 Docker）；在线上演练一遍。
