# Proposal

## Why

后端的 `GET /summary` 已经能按真实记录给出每题分类、原因和行为事实，但 E 的 `/summary` 只是占位页。题面要求"基于真实记录的总结 + 建议 + 回看"（大纲 §1.3 第 5 条、§3.2），这也是学生"看懂自己的学习情况、知道下一步"的地方。

## What Changes

- `/summary` 页面替换 E 的占位页：
  - **统计**：首次正确率、最终完成率，以及一次做对、订正后做对、需回顾三类的题数，数字直接取自 `GET /summary`；提前结束的会话加以说明。
  - **三类题目列表**：每题显示题号、知识点和题干摘要；"需回顾"的题再注明原因（答错还没改对 / 跳过了 / 没有作答）。每题都可以点开回看。
  - **回看**：在总结页内展开该题的图形、题干、作答概况（作答几次、答错几次、碰到过的常见错误答案）和图文解析。打开解析照常上报学习事件；会话已结束，事件不计入统计。
  - **鼓励语与建议**：由一个纯函数根据分类和行为事实生成。措辞只描述实际发生的行为（"打开了图文解析""看完了视频"），不说"看懂了"。
  - **再练一次**：创建新会话，进入第 1 题，旧会话和它的总结保留。
- **练习记录**（评审时加入，对应大纲 §2.4"旧会话及总结保留可查"）：
  - 后端新增 `GET /api/learners/:id/sessions`，列出这个学生最近 20 次练习及各自的统计；
  - 前端新增 `/history` 页，已结束的练习可以"查看总结"，进入 `/summary/:sessionId`；
  - 首页和总结页加上"练习记录"入口。
- 进行中的会话打开 `/summary` 时，转到答题页；会话失效时回首页。
- 首页、答题页的"已结束 → 总结页"跳转已在 E 中完成，本次只复用。
- 首页和总结页的"开始 / 再练一次"共用同一段创建逻辑，从首页中抽出来。

## Capabilities

### New Capabilities
- `summary-page`：总结页显示什么、能做什么，包括统计、分类列表、回看、再练一次，以及进行中或失效会话的跳转。
- `study-advice`：鼓励语与学习建议的生成规则：依据哪些记录、各种情况怎么说、哪些说法不允许。

### Modified Capabilities
- `practice-sessions`：新增"学生的练习记录"接口。practice-pages 只要求结束后"进入总结页"，没有规定总结页的内容，不需要改。

## Impact

- 新增：`web/src/pages/SummaryPage.tsx`（替换占位页）、`web/src/pages/HistoryPage.tsx`、`web/src/summary/advice.ts` 与测试、总结页和练习记录页的组件测试、`server/test/api-history.test.ts`。
- 修改：`web/src/pages/HomePage.tsx`（抽出开始练习的逻辑）。
- 后端只新增一个只读接口（`listLearnerSessions` 与路由），不改表结构，不加依赖。
- 不在范围内：视频回看（I）、小镇建筑展示（H）、专业学情诊断。
