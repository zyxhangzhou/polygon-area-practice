# Proposal

## Why

D（练习会话 API）、E（答题页）、F（总结页）都要回答同几个问题：这个输入合不合法、算不算对、这道题现在是什么状态、这次练习一共做对几道。这些规则先写成不碰数据库的纯函数并用单元测试锁住，接口和页面就只负责读写和展示，所有数字出自同一个口径（大纲 §2.4、§3、§4.5）。

## What Changes

- 输入处理：先规范化（去首尾空格、全角数字与全角小数点转半角、中文句号"。"转"."），再校验格式。只接受"非负整数或最多 2 位小数"。不合法的输入返回原因代码和给学生看的提示，不计入作答次数。
- 数值上限：整数部分最多 8 位（与 `numeric(10,2)` 一致），原始输入最长 32 个字符。这一条来自 B 评审的遗留事项。
- 判题：按十进制精确比较，`30`、`30.0`、`30.00` 相等。题库答案无论写成 `"30"` 还是数据库读出的 `"30.00"`，比较结果都一样。答错时识别预设的常见错误答案，并返回对应提示。
- 题目状态：根据作答和跳过记录推导 `unanswered` / `wrong` / `skipped` / `solved`，先后顺序以 `seq` 为准。
- 关卡与进度：关卡是否点亮、哪些关卡已解锁、当前该做哪道题、能否完成练习、还有几道跳过的题。
- 学习总结：每道题归入"一次做对 / 订正后做对 / 还没做对"之一（还没做对的附原因），计算首次正确率和最终完成率。练习进行中和结束后用同一个函数、同一个口径；进行中时"还没做对"表示"目前还没做对"，结束后即总结页上的"需回顾"。
- 每道题附带行为事实（作答几次、答错几次、跳过几次、碰到过哪些常见错误、是否打开图文解析、是否播放或看完视频），供 F 生成鼓励与建议。

## Capabilities

### New Capabilities
- `answer-grading`：学生输入的规范化与合法性校验、精确判题、常见错误识别。
- `practice-progress`：每道题的状态推导、关卡点亮与解锁、当前题、能否完成练习。
- `learning-summary`：每道题的最终分类、首次正确率与最终完成率、供建议使用的行为事实。

### Modified Capabilities
（无）`question-bank` 与 `practice-records` 的要求不变。

## Impact

- 新增：`server/src/grading/`（输入处理、判题、进度、总结），对应单元测试 `server/test/grading-*.test.ts`。
- 不改表结构、不加接口、不加依赖。D 调用这些函数并把结果写入 `attempts.normalized_value`、`attempts.matched_mistake`。
- D 要遵守的约定（写在 design 中）：传入的记录必须带 `seq`；会话结束后产生的学习事件不传给总结函数。
