# Proposal

## Why

D 的接口已经可以完成一次完整练习，但学生只能看到项目骨架页。评分重心里的"前后端状态一致、刷新恢复、不显示假成功"最终要在浏览器里体现（大纲 §2.2、§5）。E 做答题主流程的前端，让学生在浏览器里独立做完一组练习。

## What Changes

- 前端页面（React，无路由库，按路径切换 3 个页面）：
  - `/`：首页，开始练习 / 继续练习 / 再练一次。
  - `/practice/:qid`：答题页，包括进度（关卡 x/4、题目 x/12、各题状态）、SVG 图形、题干、文本输入框加固定单位、判题反馈，以及"再试一次 / 看图文解析 / 先跳过"。
  - `/summary`：占位页，F 再做总结内容。
- 结束练习：
  - 全部题都处理过后，显示"完成练习"；
  - 随时可以"提前结束"，需要二次确认；
  - 结束后进入 `/summary`。
- 一个统一的接口客户端，把每次请求的结果分成 3 类：
  - **成功**；
  - **被拒绝**：后端返回 4xx 和错误码，前端按错误码处理；
  - **结果不确定**：断网、超时、5xx 或响应不是 JSON。前端提示"再点一次"，并沿用同一个幂等键。
- 写请求按顺序执行，前一个确认后再发下一个。学习事件（打开图文解析）确认后，才提交后面的作答，保证"先看解析再答对"被正确归类。
- 前端不推算任何进度：题目状态、解锁、点亮、分类、统计，一律以后端返回的 `session` 和 `result` 为准，不做乐观更新。
- 前端测试：`web` 加入 Vitest、jsdom 和 Testing Library；根目录的 `npm test` 同时跑前后端测试，CI 不用改。
- 前端直接导入后端的响应类型（只导入类型），后端改了响应结构时，前端类型检查会报错。

## Capabilities

### New Capabilities
- `practice-pages`：首页、答题页、结束练习的页面行为，包括进度展示、图形绘制、判题反馈、解析查看、关卡间导航和刷新恢复。
- `practice-client-sync`：前端与后端保持一致的规则，包括请求结果的分类与提示、幂等键的使用、写请求的顺序、提交中禁用、本地只保存标识。

### Modified Capabilities
（无）

## Impact

- 新增：`web/src/` 下的页面、组件、接口客户端、图形绘制和前端测试。
- 修改：
  - `web/package.json`：新增开发依赖 vitest、jsdom、@testing-library/react、@testing-library/user-event、@testing-library/jest-dom；
  - 根目录 `package.json` 的 `test` 脚本；
  - README（前端测试的运行方法）。
- 不改后端接口。
- 不在范围内：
  - 小镇动画、圆圆（H）；
  - 视频按钮（I），虽然题目有 `hasVideo`，E 不显示视频入口；
  - 总结内容（F）。
