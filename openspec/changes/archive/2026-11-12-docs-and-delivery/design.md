# Design

## Context

- 题面"提交要求"共 4 项：可运行成果与源码、README、AI 协同开发记录、验证与限制说明。题面还要求注明实际投入时间、复用内容、未完成项，素材注明来源。
- 现有文档：
  - `README.md`：启动、测试、接口、配置、故障、日志；
  - `docs/project-outline.md`：大纲与决策；
  - `docs/ai-log-notes.md`：按 change 记录的过程；
  - `docs/verification.md`：浏览器实跑记录与截图；
  - `docs/deploy.md`：部署与运维；
  - `docs/video-assets.md`：视频素材来源。
- 会话原文保存在本机 Claude Code 的会话记录中，可以从中摘录原话。
- main 上是 squash 合并，逐条提交的历史保留在 GitHub 的 PR #1–#9 中。

## Goals / Non-Goals

**Goals:**
- 评审只读 README，就能知道这个项目是什么、怎么跑、结构如何、数据怎么算、有什么限制，并能找到其他文档。
- AI 协同记录可信：引用原话，写明本人做出的判断，以及 AI 出错后是怎么被发现的。
- 所有关于"已验证"的说法都有对应的执行结果或记录。

**Non-Goals:**
- 不重写已有文档的内容，只做汇总、链接和校对。
- 不做幻灯片。

## Decisions

### D1 README 的结构

顺序为：
1. 简介 + 线上地址 + 一张截图；
2. 功能与题面要求的对照表；
3. 快速开始（保留现有内容）；
4. 系统结构；
5. 数据模型；
6. 统计口径；
7. 接口（保留）；
8. 可靠性；
9. 取舍；
10. 测试；
11. 部署、日志与回退（摘要 + 链接）；
12. 文档索引；
13. 提交说明（投入时间、复用、未完成项，链接 `docs/delivery.md`）。

系统结构用 Mermaid 图，GitHub 会直接渲染。数据模型列出表、关键字段和约束，与 `server/src/db/schema.ts` 核对。

### D2 三段代表性 AI 协同记录

按题面列出的环节各选一段，覆盖方案设计、部署排障、编码与调试：
1. **方案设计**：D 中"幂等重放返回什么"的讨论。本人提出"先错后对，再重放第一次请求"的情形，AI 给出方案，本人确认；E 评审时又按显示问题修订了规则。验证：对应的测试。
2. **部署排障**：G 中代理层数的实测。AI 先按假设设为 1，本人看线上日志后发现是 `10.x`，设为 2 时出现 Cloudflare 地址，最终确定为 3。这段展示了 AI 方案有误、如何发现和修正，以及最后的验证。
3. **编码与调试**：H 中由本人提出的视觉要求，以及 AI 实现中的错误：
   - 首页读到进度时误播建造动画，由测试发现；
   - class 同名导致面板被撑宽，由浏览器实跑发现；
   - 手机宽度下反馈在屏幕外，由评审模型提示后实测发现。

每段的格式：任务输入（原话节选）→ AI 产出（摘要 + 关键片段）→ 本人判断 / 修改 → 验证结果（测试名、实跑记录）。节选会隐去邮箱等个人信息。

### D3 `docs/delivery.md`

- 测试：命令、各套件数量、执行日期，并说明 CI 每次 PR 都会跑。
- 已验证场景：与题面要求逐条对照，并链接到对应的测试文件或 `verification.md` 中的记录。
- 已知问题与限制：从 `deploy.md`、`video-assets.md`、计划的 Out of scope 中汇总。
- 未完成项：方格图估算题、其余 10 题的视频、跨设备找回、自动备份。
- 投入时间、AI 费用：由本人提供。仓库能证明的只有提交时间范围（11/10 23:00 到 11/12），会同时写出。
- 复用内容：开源依赖（列主要的）、字体（Noto / Fontsource，OFL）。题目、解析、视频脚本由 AI 编写、本人审核。

### D4 干净环境验证

- 在临时目录中 `git clone` 仓库，不带本机的 `.env`、`node_modules` 和数据卷。
- 按 README 用 `docker compose`，以不同的 project name 和端口启动（避免与本机已有的容器冲突）。
- 跑 `npm run smoke`；再 `npm ci && npm test`（测试使用临时的 Postgres）。
- 记录用到的命令和结果。发现 README 有误就改 README。
- 结束后删除临时容器和数据卷。

### D5 演示脚本与演练

约 8 分钟，流程：
1. 首页与引导；
2. 答对，看建造；
3. 答错，看图形提示和圆圆的反馈；
4. 看视频讲解；
5. 跳过后过关；
6. 刷新，进度恢复；
7. 总结页与练习记录；
8. 工程侧：测试、CI、部署、日志。

开场前 5 分钟打开线上地址唤醒实例。线上不可用时，改用本地 `docker compose up --build`。

演练在线上进行，会新建一个演示用的匿名学生。演练时备份并恢复浏览器里本站的 `polygon.*` 键，不影响本人原有的练习记录。

## Risks / Trade-offs

- [引用会话原文可能带出不该公开的信息] → 只摘录与任务相关的句子，隐去邮箱、账号、会话以外的内容。
- [干净环境验证要重新构建镜像，时间较长] → 后台运行，同时写文档。
