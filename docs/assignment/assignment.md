# 全栈开发岗面试实践题（二选一）— 文字版

> 原件：[全栈开发岗面试实践题（二选一）.pdf](./全栈开发岗面试实践题（二选一）.pdf)。本文件为便于检索与引用的文字转录，以原件为准。
> **本项目选择：选题一（多边形面积计算）。**

请从以下两道题目中任选一道，借助AI编程工具，独立完成一个可在电脑浏览器中运行、供小学五年级学生使用的全栈网页Demo，包含前端、后端接口和数据保存能力。

语言、框架、数据库和AI工具不限。请自主设计页面、操作流程和反馈方式，在完成核心工程链路的同时，呈现适合小学五年级学生、清晰连贯且有趣的学习体验，并说明关键技术与体验设计取舍。

**本次重点考察AI协同开发、后端与全栈工程实现、部署排障和质量验证能力，同时关注学生能否独立使用、愿意持续练习，以及能否通过反馈和总结了解自己的学习情况。教学内容应基本正确；不以专业教研深度、复杂游戏机制或视觉精修作为主要评分依据。**

## 两道选题共同的工程要求

1. **完整业务链路**：前端通过后端接口完成核心操作。题目或场景配置、练习记录和总结所需数据由后端管理并持久化保存，不能仅用静态页面或浏览器本地存储代替。数据库可选用SQLite等轻量方案，无需专门建设注册登录系统，可使用匿名练习标识。
2. **基本可靠性**：围绕所选题目处理输入校验、重复操作、页面刷新后的记录恢复，以及接口或外部服务失败等实际问题。说明哪些问题已处理、哪些仍有限制，避免出现页面显示成功而后端未保存等状态不一致。
3. **部署与排障**：提供清晰的安装、配置和启动步骤，能够在干净环境中按说明启动。说明前端、后端、数据库和外部服务的连接关系、日志查看方式，以及发布失败后的回退或恢复办法。可本地部署；如提供线上地址，需能说明实际部署过程，无需购买服务器或付费服务。
4. **验证核心逻辑**：为核心业务逻辑提供可重复执行的自动化测试，至少覆盖一个正常流程和两个重要异常或边界场景，并说明如何执行。测试应验证真实行为，而非只验证页面可以打开或接口返回成功。
5. **真实的AI协同开发**：在需求拆解、方案设计、编码、调试、测试或部署中实际使用AI。保留能展示任务上下文、AI产出、本人判断和最终验证结果的代表性过程记录，说明至少一次AI方案或代码出现问题后，你如何发现、修改并验证。

请优先完成核心链路，提交时注明实际投入时间、复用内容及未完成项。不要求微服务、Kubernetes或复杂架构；如选择使用，应能解释其必要性。教学题目、图片、音视频等素材允许复用适当的现有资源或借助AI制作，请注明来源。

## 选题一：小学五年级"多边形面积计算"练习Demo

**设计目标**：让学生能够独立完成一组练习，获得及时反馈，通过解析理解错误，并愿意继续练习。

### 基本要求

1. **题目练习**：围绕小学五年级"多边形面积计算"，提供至少10道练习题，支持学生逐题作答。
2. **答案判断与正向反馈**：由后端校验作答并返回判断结果，保存作答和尝试记录；答对、订正成功或完成阶段目标时，给予及时、恰当的正向反馈。反馈形式自行设计，如鼓励语、轻量动画或阶段成就；答错时应友好地帮助学生继续尝试。需合理处理空输入、非法输入、数值精度，以及重复提交对记录和统计的影响。
3. **两种解析方式**：答错时可查看解析。所有题目均需提供非视频解析；其中至少2道代表性题目同时提供可播放的视频解析，让学生能够自主选择非视频或视频解析。
4. **趣味性与完整练习体验**：设计并实际实现至少一种能帮助学生愿意继续练习的互动机制，例如情境任务、分阶段挑战、进度里程碑或角色陪伴，形式自行选择。让学生清楚当前练习进度，顺畅完成作答、获得反馈、学习解析和继续练习；互动应与练习过程结合，避免仅以装饰或重复弹出奖励代替体验设计。
5. **学习总结**：完成整组练习后，基于后端保存的真实作答记录，向学生呈现清晰、易懂的总结：完成了多少题、哪些题掌握较好、哪些题经过订正才做对或仍需回顾，以及接下来可以怎样巩固。除统计数字外，应提供与本次表现相关的鼓励和具体建议，并能方便地回看相关题目或解析。说明首次作答与重试如何计入统计，保证页面展示与数据口径一致；总结与建议应以实际记录为依据，不要求作出专业学情诊断。

保留至少10道题及至少2道代表性题目的视频解析要求。题目、解析和视频可选用适当的现有素材，无需自行制作精美视频。请重点展示题目组织、后端判题、记录保存、解析播放和总结统计如何形成完整链路。数学选题不要求运行时调用大模型，但必须展示开发过程中实际使用AI的证据。

## 选题二：小学五年级英语口语练习Demo（未选）

**设计目标**：让学生通过语音与AI进行英语对话，获得适当帮助和鼓励，愿意开口并持续交流。

1. **对话场景**：提供至少两个可选对话场景，具体场景自行设计。
2. **实时语音与多轮对话**：支持学生通过语音与AI进行连续多轮英语对话，并根据实际表达和上下文作出英语语音回应。可调用现成的语音识别、大模型和语音合成服务，也可使用端到端语音服务。核心对话必须真实运行，不能用预设问答或固定录音模拟；需妥善管理会话状态，并处理录音权限拒绝、空语音、响应超时或服务失败等情况。可采用逐轮录音方式，不强制实现实时打断。
3. **内容与求助支持**：对话内容适合小学五年级学生；学生听不懂或需要求助时，能够获得合适的帮助，具体方式自行设计。
4. **反馈与鼓励**：对学生的实际表达作出恰当回应，在主动开口、完成交流任务或改正表达后给予具体、自然的鼓励；出现明显表达问题时，以适合学生理解的方式提供示例或引导重说，帮助学生继续交流。
5. **趣味性与交互体验**：整体交互清晰、顺畅，便于学生独立操作。设计并实际实现至少一种促进学生开口和持续交流的方式，例如角色对话、情境任务、阶段目标或根据学生回答自然追问，形式自行选择。让学生知道当前在做什么、何时轮到自己说话，以及怎样求助和结束练习。
6. **学习总结**：练习结束后，基于实际对话记录，用学生能理解的语言总结本次练习的场景或任务、表达得较好的地方，以及值得改进的词句，并提供具体示例或下一次练习建议。总结应包含恰当的鼓励，帮助学生知道自己完成了什么、下一步怎样进步，而非仅展示对话轮数或笼统评价。对话记录与总结应可查询，支持刷新后恢复已有练习或查看本次结果。说明保存了哪些数据、如何关联会话，以及上下文长度的处理方式；不要求开发专业发音评分模型。

## 提交要求

1. **可运行成果与完整源码**：提供演示链接或可启动的项目文件、完整前后端代码、必要的数据库初始化或迁移文件，以及有实际开发过程的Git提交记录。面试时应能够实际操作和演示。
2. **README**：写明环境依赖、安装与启动命令、配置示例、数据库初始化、测试执行和部署步骤。说明系统结构、核心接口、数据模型，以及日志位置、常见故障排查和回退或恢复办法。密钥由环境变量等方式配置，不放入前端代码或提交材料。
3. **AI协同开发记录**：选取2—3段代表性记录，可用对话节选、截图或工具导出文件，展示任务输入、AI产出、本人修改和验证结果。附简要说明：哪些工作由AI承担、哪些关键判断由本人完成、遇到过什么错误，以及如何纠正。无需提交全部聊天记录，请隐去密钥和无关信息。
4. **验证与限制说明**：提交自动化测试及执行结果，简要列出已验证场景、已知问题、未完成项和实际投入时间。使用外部AI服务时，说明服务依赖和大致调用成本；无法提供在线服务的，请提供明确的配置与复现步骤，不要求为面试购买付费服务。
