# 验证记录

自动化测试由 CI 在每次推送时运行（`npm test`：后端集成测试连真实 Postgres，前端组件测试用 jsdom）。本文件记录需要真实环境的手工验证。

## E · 答题主流程前端（2026-11-11）

**环境**：
- 本机执行 `npm run build`，然后用 `PORT=3100 npm start` 以生产模式启动，前端和接口由同一个服务提供。
- 数据库是本地开发库（Docker Compose 的 Postgres 17）。验证前库里没有表，服务启动时执行了迁移和种子。
- 浏览器由 AI 用浏览器自动化工具（ego-browser）操作。
- 浏览器窗口处于最小化状态，无法截图，下面的证据用页面状态和数据库查询代替。

**未在真实环境验证**：
- "作答已保存但响应丢失后重试"在真实网络下不好制造。这一场景由以下测试覆盖：
  - 后端集成测试"同键重复提交：只一条记录，结果相同"和"等锁超时后用同一个键重试只写入一条"；
  - 前端组件测试"结果不确定后再提交一次，拿到首次结果"。
- 多标签页同时操作由前端组件测试覆盖。
- 下面两种情况在实跑之后才发现。实跑时，后端只在题目已经加载完的页面上停过，结果不确定的也只有作答。
  - 题目或解析读取失败：页面会一直停在"正在读取"，现在改为显示"重新读取"。
  - 等待重试时还能切到别的题：现在改为在页面层显示"再提交一次"，并锁住题目导航。

  这两项都已补上前端组件测试，没有在浏览器中重跑。
