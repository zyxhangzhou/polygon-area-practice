## 1. 我对题目的理解

### 1.1 一句话目标
做一个**前端 → 后端接口 → Postgres** 全链路打通的练习网页：五年级学生能独立做完一组多边形面积题，答错有友好引导和解析（图文 + 视频），做完看到一份**基于真实作答记录**的总结。

### 1.2 评分重心（按题面权重排序）
1. **工程链路与可靠性**：后端判题、持久化、幂等、刷新恢复、前后端状态一致
2. **质量验证**：自动化测试覆盖真实行为（正常流程 + ≥2 个异常/边界）
3. **部署与排障**：干净环境可启动、线上可访问、日志与回退说明
4. **AI 协同开发**：真实过程记录，至少一次"AI 出错 → 发现 → 修正 → 验证"
5. **学生体验**：能独立使用、愿意继续练、能看懂自己的学习情况

**不作为重点**：视觉精修、复杂游戏机制、专业教研深度。

### 1.3 题面"硬指标"清单
| # | 要求 | 本方案对应 |
|---|---|---|
| 1 | ≥10 道题，逐题作答 | 12 道题，4 个关卡 |
| 2 | 后端判题 + 保存尝试记录 + 正向反馈 | `POST /attempts`，attempts 表，答对/订正/过关三类反馈 |
| 2 | 空输入、非法输入、精度、重复提交 | 输入规范化 + 十进制精确比较 + 幂等键 |
| 3 | 全部题有非视频解析，≥2 题有视频解析 | 12 题图文分步解析，2 题加视频 |
| 4 | ≥1 种互动机制，与练习结合 | "图形小镇建造师"分关卡建造 + 向导角色 |
| 5 | 基于真实记录的总结 + 建议 + 回看 | 总结接口由 attempts 实时计算，可跳转回看解析 |
| 共同 | 不能用 localStorage 代替持久化 | localStorage 只存匿名标识和 sessionId，进度全部从后端取 |

## 2. 学生体验设计

### 2.1 互动机制："图形小镇建造师"
- 学生扮演小镇建造师，**向导角色"小方"**（一只拿着尺子的小狐狸）陪伴全程。
- 4 个关卡 = 小镇的 4 个建筑，每关 3 题；**每答对一题，建筑就盖好一部分**，3 题全部完成则建筑点亮。
- 关卡顺序与知识推导顺序一致：平行四边形 → 三角形 → 梯形 → 组合图形（后面的公式由前面推导而来）。
- 反馈与练习绑定，不靠弹窗堆奖励：
  - **首次答对**：建筑长高一截 + 简短鼓励语
  - **订正答对**：专门肯定"改正"（"看懂解析再做对，这才是真本事！"）
  - **过关**：建筑点亮动画 + 小方的一句话点评本关表现
  - **答错**：小方给出温和提示（如"三角形面积别忘了 ÷2 哦"），提供"再试一次 / 看图文解析 / 看视频解析"三个选项

### 2.2 页面流程
```
首页（小镇地图 + 开始/继续练习）
  └─> 答题页（顶部进度条：关卡 x/4、题目 x/12；图形 SVG；题干；数字输入框 + 固定单位）
        ├─ 答对 ─> 反馈 ─> 下一题
        ├─ 答错 ─> 提示 ─> [再试一次] [图文解析] [视频解析(有则显示)] [先跳过]
        └─ 关卡完成 ─> 建筑点亮 ─> 下一关
  └─> 总结页（统计 + 每题状态 + 鼓励与建议 + 回看题目/解析 + 再练一次）
```
- 刷新任何页面都能回到原进度（从后端恢复）。
- 允许"先跳过"，跳过的题在总结里计为"需回顾"，并可在总结页回去重做。

### 2.3 题目设计（12 题，草案）
单位已在输入框后固定，学生只填数字。

| 关卡 | # | 题目 | 答案 |
|---|---|---|---|
| ① 平行四边形·面包店 | 1 | 平行四边形，底 8 cm，高 5 cm，求面积 | 40 cm² |
| | 2 | 平行四边形，底 6.5 m，高 4 m，求面积 | 26 m² |
| | 3 | 平行四边形面积 48 dm²，底 12 dm，求高 | 4 dm |
| ② 三角形·帐篷营地 | 4 | 三角形，底 10 cm，高 6 cm，求面积 🎬 | 30 cm² |
| | 5 | 三角形，底 4.2 m，高 3 m，求面积 | 6.3 m² |
| | 6 | 直角三角形，两条直角边 9 cm、12 cm，求面积 | 54 cm² |
| ③ 梯形·小桥 | 7 | 梯形，上底 4 cm，下底 8 cm，高 5 cm，求面积 | 30 cm² |
| | 8 | 梯形，上底 3.5 m，下底 6.5 m，高 4 m，求面积 | 20 m² |
| | 9 | 水渠横截面是梯形，上口 12 m，渠底 8 m，深 3 m，求横截面面积 | 30 m² |
| ④ 组合图形·小镇广场 | 10 | "小房子"：长方形 10×6 cm 上接底 10 cm、高 4 cm 的三角形 🎬 | 80 cm² |
| | 11 | L 形地块：10×8 m 长方形缺去一角 4×3 m，求面积 | 68 m² |
| | 12 | 平行四边形菜地，底 25 m，高 12 m，每平方米收白菜 3 kg，共收多少 | 900 kg |

- 🎬 = 同时提供视频解析：第 4 题（三角形为什么要 ÷2）、第 10 题（组合图形的分割法）。
- 第 6 题专门设计"直角边就是底和高"的易错点；第 3 题考逆运算；第 12 题考实际应用。
- 每题的图文解析分 3 步左右：**看图找条件 → 选公式 → 代入计算**，并附一条"易错提醒"。
- 每题可预设 1~2 个**常见错误答案**（如第 4 题答 60 = 忘了 ÷2），后端识别后给针对性提示。

## 3. 统计口径（题面要求明确说明）

每道题在一次练习中只归入**一个**最终状态，全部由 `attempts` 表实时计算：

| 状态 | 判定规则 | 总结页文案 |
|---|---|---|
| **一次做对（掌握）** | 第 1 次有效作答即正确 | 掌握得很好 |
| **订正后做对** | 第 1 次有效作答错误，之后某次正确 | 经过订正做对了 |
| **需回顾** | 从未答对（含跳过、答错后放弃） | 还需要再看看 |

- **无效输入**（空、非数字、负数、格式错误）**不计入尝试次数**，后端返回提示即可。
- **重复提交**（同一幂等键）只记一次，返回第一次的结果。
- **已答对的题再提交**：不再写入新尝试、不改变状态。
- 额外记录：是否在答对前看过解析、看的是图文还是视频（总结里用于建议，如"第 4 题看了视频后做对了"）。
- 正确率指标：**首次正确率** = 一次做对题数 / 总题数；**最终完成率** = (一次做对 + 订正后做对) / 总题数。

## 4. 系统设计

### 4.1 技术栈
| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | React + Vite + TypeScript | 熟悉、构建快；图形用 SVG 按参数绘制，不依赖图片素材 |
| 后端 | Node.js + Fastify + TypeScript | 内置 schema 校验与 pino 结构化日志，`inject` 便于集成测试 |
| 校验 | zod（前后端共享类型） | 一份定义两端复用 |
| 数据库 | PostgreSQL | 唯一约束 + 事务保证幂等与一致性 |
| DB 访问/迁移 | Drizzle ORM + drizzle-kit（待定，备选 Kysely + SQL 迁移） | 迁移文件入库，类型安全 |
| 测试 | Vitest + 真实 Postgres（Docker / CI service） | 不用内存模拟库，避免行为差异 |
| 本地运行 | Docker Compose（Postgres + 应用） | 干净环境一条命令启动 |
| 线上 | Render 免费 Web Service + Render 免费 Postgres（`render.yaml`） | 同平台内网连接，30 天有效期足够覆盖展示 |
| CI | GitHub Actions | 每次推送跑测试，留下可查记录 |

生产环境由 Fastify 同时托管前端构建产物，**单服务、单端口**，部署和排障都简单。

### 4.2 架构
```
浏览器 (React SPA)
   │  fetch /api/*（JSON）
   ▼
Fastify 服务（同时托管静态前端 + 视频）
   ├─ 路由层：参数校验（zod）
   ├─ 服务层：判题、进度、统计（纯函数，可单测）
   └─ 数据层：Drizzle → PostgreSQL
日志：pino → stdout（本地终端 / docker logs / Render Logs）
```

### 4.3 数据模型（草案）
- **questions**：id、stage、order、shape_type、prompt、figure(jsonb，SVG 参数)、answer(numeric)、unit、explanation(jsonb，分步解析)、video_url、common_mistakes(jsonb)、knowledge_point
- **stages**：id、order、name、building_name、intro
- **learners**：id(uuid)、nickname(可选)、created_at —— 匿名标识
- **practice_sessions**：id、learner_id、status(in_progress / completed)、started_at、completed_at；部分唯一索引保证每个学生同时只有一个进行中的练习
- **attempts**：id、session_id、question_id、client_attempt_id(**唯一**)、raw_input、normalized_value、is_correct、attempt_no、matched_mistake、created_at
- **explanation_views**：session_id、question_id、kind(text / video)、created_at
- **question_skips**（或合并进事件表）：session_id、question_id、created_at

题库通过迁移 + 种子脚本写入，**答案只存在后端**。

### 4.4 核心接口（草案）
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查（含数据库连通性） |
| POST | `/api/learners` | 创建匿名学生，返回 learnerId |
| POST | `/api/sessions` | 开始或继续练习（已有进行中的则返回它） |
| GET | `/api/sessions/:id` | 会话状态：关卡、每题状态、当前题 —— **刷新恢复靠它** |
| GET | `/api/sessions/:id/questions/:qid` | 题目详情（**不含答案和解析**） |
| POST | `/api/sessions/:id/attempts` | 提交答案 `{questionId, clientAttemptId, answer}` → 判题结果 + 最新进度 |
| GET | `/api/sessions/:id/questions/:qid/explanation` | 解析（仅在答错、跳过或已答对后可取），同时记录查看 |
| POST | `/api/sessions/:id/questions/:qid/skip` | 跳过 |
| POST | `/api/sessions/:id/complete` | 结束练习 |
| GET | `/api/sessions/:id/summary` | 学习总结（由 attempts 实时计算） |

### 4.5 判题与输入处理
- 规范化：去首尾空格、全角转半角、中文句号"。"转"."；
- 合法格式：非负十进制数，最多 2 位小数；拒绝空串、字母、负数、科学计数法、多个小数点；
- 比较：按十进制精确比较（字符串转定标整数），`30`、`30.0`、`30.00` 视为相等，**不用浮点数直接比较**；
- 识别预设的常见错误答案，返回针对性提示。

## 5. 可靠性设计

| 问题 | 处理方式 |
|---|---|
| 重复提交 / 连点 / 网络重试 | 前端生成 `clientAttemptId`，数据库唯一约束 + `ON CONFLICT DO NOTHING`，重复请求返回首次结果；按钮提交中禁用 |
| 并发提交导致 attempt_no 错乱 | 事务内对会话行加锁（`SELECT ... FOR UPDATE`）后再计算序号并写入 |
| 页面显示成功但后端未保存 | 不做乐观更新：只有后端提交成功后才显示判题结果；失败时提示"没保存上，再点一次"，用同一幂等键重试 |
| 刷新后进度丢失 | localStorage 只存 learnerId / sessionId；进度、记录一律从后端拉取；sessionId 无效时自动新建 |
| 前端拿到答案 | 题目接口不返回答案；解析接口按状态限制 |
| 非法输入 | 前后端双重校验，后端为准；无效输入不计尝试 |
| 已答对的题再提交 | 返回"已完成"，不写记录、不改统计 |
| 接口失败 / 数据库断开 | 统一错误格式；前端友好提示 + 重试；`/api/health` 检测数据库 |
| 视频加载失败 | 提示并引导看图文解析 |
| 公网滥用 | 简单的请求频率限制（`@fastify/rate-limit`） |

**已知限制（初稿）**：无登录，换浏览器或清除缓存会生成新的匿名身份，旧记录仍在库中但无法找回；Render 免费数据库无自动备份、约 30 天后过期；免费实例闲置会休眠，首次访问需等待约 30 秒。

## 6. 测试计划
- **单元测试**：输入规范化与校验、十进制比较、常见错误识别、统计口径计算。
- **接口集成测试（真实 Postgres）**：
  1. 正常流程：开始练习 → 逐题作答 → 完成 → 总结数字与预期一致
  2. 重复提交同一 `clientAttemptId` 只记一次，统计不变
  3. 先答错再订正，计为"订正后做对"，首次正确率不受影响
  4. 非法输入不计尝试次数
  5. 未作答时请求解析被拒绝；答错后可获取
  6. 已答对的题再次提交不改变记录
  7. 并发提交时尝试序号不重复
- **CI**：GitHub Actions 启动 Postgres service，推送即运行。
- 测试结果存档到 `docs/verification.md`。

## 7. 部署与运维
- **本地**：`docker compose up` → 自动迁移 + 种子 → 打开 `http://localhost:3000`；另附不用 Docker 的手动步骤。
- **线上**：Render Blueprint（`render.yaml`）声明 Web Service + Postgres；推送到 main 自动部署；启动前执行迁移。
- **日志**：pino JSON 日志输出到 stdout；本地看终端或 `docker compose logs`，线上看 Render Logs。
- **回退**：Render 控制台一键回滚到上一次成功部署；迁移只做向前兼容的变更；题库可通过种子脚本重建；作答记录用 `pg_dump` 导出。
