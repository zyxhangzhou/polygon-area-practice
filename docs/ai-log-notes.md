## 2026-11-11 · change A 的 PR 评审（子代理）· session fab477d6

本人要求另起一个子代理审 PR #1。子代理只读代码，用临时脚本复现问题，找到 3 个真问题：

| # | 问题 | 子代理如何证实 | 处理 |
|---|---|---|---|
| 1 | 健康检查只用 `Promise.race` 超时，超时的查询仍占着连接；数据库卡住后连接池被占满，恢复后仍一直 503，`app.close()` 也关不掉 | 写一个可"冻结"的 TCP 代理复现：10 个连接全卡住，解冻后仍 503，`close()` 8 秒未结束 | 连接池加 `query_timeout` 与 `keepAlive`；关闭流程加 10 秒强制退出、忽略重复信号 |
| 2 | 没有 `setErrorHandler`，Fastify 自带的 400 格式与约定的 `{error:{code,message}}` 不同，500 会把内部错误信息返回前端 | 发错误 JSON、抛异常实际复现 | spec 新增"统一错误响应格式"需求与 2 个场景，再实现 |
| 3 | README 让人在 `.env` 里改 `TEST_DATABASE_URL`，但测试不读 `.env` | 读代码，与 README 自身的说明矛盾 | 改为在 shell 中设置 |

- 测试缺口：原来的"数据库不可达"测试用 `127.0.0.1:1`，连接被立即拒绝，删掉超时逻辑测试也照样通过。新增"能连上但不回应"的假服务器测试，以及用冻结代理的"卡住后恢复"测试。
- **验证方式**：先实现修复并让新测试通过（34 个），再临时撤掉修复：撤掉 `query_timeout` 后恢复测试失败，撤掉错误处理后 2 个错误格式测试失败。说明测试确实能抓到这些问题。
- 本人取舍：测试库隔离推迟到 B（B 才开始写数据）；`concurrently` 不做（收益太小）。

## 2026-11-11 · change B（data-model-question-bank）· session fab477d6

- **AI 对大纲草案的修正（经本人评审确认）**：
  - 幂等键从"全局唯一"改为"会话内唯一"：全局唯一时，别的会话撞上同一个键会导致写入失败，甚至可能把别人的结果返回给当前会话。
  - 迁移放进启动流程：Render 免费档不支持 pre-deploy 命令。
- **用测试防止题库内容出错**：12 道题的内容由 AI 编写，答案和图形参数可能对不上，人工核对容易漏。新增"自洽性测试"：按图形参数用公式重新计算每道题，结果必须等于答案；同时校验常见错误答案不等于正确答案。
- **AI 自己发现的问题**：
  - design 初稿写"pg 会重试连接"，与 pg 的实际行为不符，写 tasks 前已改正。
  - 数据库不可达时，启动报错只有 `timeout expired`，看不出连的是哪个地址。改为同时输出连接目标（不含密码），并展开 `AggregateError`。
- **防误删**：测试的 global setup 会 `DROP SCHEMA`，因此先检查库名必须以 `_test` 结尾。用 `TEST_DATABASE_URL=.../polygon` 实测会被拒绝，开发库未受影响。
- **验证方式**：
  - 73 个测试全部通过：题库组成、答案、解析覆盖、种子可重复执行、7 类数据库约束、启动准备、自洽性。
  - 用独立的 compose 项目在全新数据卷上执行 `up --build`：库中有 12 题、1 条迁移记录；`restart` 后仍是 12 题、1 条迁移记录。

### PR #2 评审：本人发现种子无法调整顺序（AI 出错 → 发现 → 修正 → 验证）

- **AI 方案**：种子按 ID 逐行 `INSERT ... ON CONFLICT (id) DO UPDATE`，同时 `(stage_id, position_in_stage)` 与 `stages.position` 上有立即生效的唯一约束。
- **本人意见**：逐行 upsert 遇到立即生效的唯一约束，可能会有问题。
- **AI 复现**：在测试库上验证了 4 种情况，全部报 23505：
  - 同一关内交换两道题的顺序；
  - 交换两个关卡的顺序；
  - 种子数据里两道题位置重复；
  - 用新 ID 顶替旧题。

  种子在服务启动时执行，失败就退出。所以只要有人调整了题目顺序，部署后服务就起不来，而报错只有一个约束名。
- **修正**：
  - 新增自定义迁移 `0001`，把两个位置约束改为 `DEFERRABLE INITIALLY DEFERRED`，提交时才检查唯一性。
  - 种子写库前先检查数据自身的一致性，出错时报出题号。
  - 规定题目 ID 永久有效：库中有种子之外的题时，给出明确的错误说明。
  - 规格新增 3 个场景。
- **验证**：
  - 先实测：改成延迟约束后，交换顺序的两种情况通过。
  - 新增 3 个测试，共 76 个，全部通过。
  - 临时删掉迁移 `0001` 再跑，交换顺序的测试失败，说明这个测试确实依赖修复。
- **过程中 AI 的一个失误**：想撤销 Prettier 对生成文件的改动时，执行了 `git checkout`，结果把迁移日志恢复成了不含 `0001` 的旧版本。跑完检查后发现，用 drizzle-kit 重新生成了日志条目。以后改为把 `server/drizzle/meta` 加入 `.prettierignore`，不再手动处理生成文件。
